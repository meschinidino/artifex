## Problem Statement

Code is write-only for agents; humans judge systems by behavior and proof.
Artifex re-aims from factory floors for code-literate viewers (files, endpoints,
tables) to a toaster panel for code-indifferent builders: ask in chat, watch
the agent build in real time, poke the system with your own inputs, trust the
proofs. Nobody reads code, everybody judges toast.

## What Makes This Cool

- The loop is the demo (Moon 1, added): describe, machines rise, poke with your
  own input, green proof. One story with a beginning, middle, and end.
- Trust with teeth (Moon 2, added as facturas via D3=A): the first loop files
  a real monotributo invoice against ARCA homologacion, and a real test CAE
  comes back through the airlock. A tax filing is the strongest possible proof
  of "communicate in a way I can actually trust."
- The airlock beat: everything crossing the machine boundary shown in plain
  words ("sending this invoice data to ARCA homologacion, nothing else"),
  secrets masked, credentials local-only, nothing sensitive in logs or video.
- Nutrition-label closer (Moon 3, added): every system carries a shareable
  behavior card (what goes in, what comes out, proof it works, what changed).
- The stunt (Moon 4, added): Dino builds it chat-driven without opening a
  file, recorded. Rides free on his normal workflow.
- Frame: "the age of personal software." Anyone can repeat the flow for their
  own life. Greenfield now; existing codebases are the 10x later (Q5).

- ARCA homologacion only, never production from this demo (confirmed).

  override); no production URL or production cert ever on the demo machine;

## Premises

1. Humans judge behavior and proof, never code. Code and unit tests are
   agent-private. (P1, agreed)
2. Trust needs narration plus E2E proof together. Unproven narration is never
   shown as fact. (P2, agreed)
3. The realtime visual floor is required for v1. Chat plus proof cards alone
   would not be Artifex. This is the biggest 10-day risk and was challenged
   explicitly before being kept. (P3, agreed)
4. Hackathon scope is greenfield only. (P4, agreed)
5. The demo is the facturas loop on homologacion with the airlock beat and the
   nutrition-label closer, as a recorded video. Compress stays a warm fallback
   if homologacion access takes more than about two days. (P5, locked by D3=A)
6. Distribution for now is repo plus video; local-first run stays; real
   packaging (one-click run, hosted try-it) waits until after. (P6, restated
   plainly after confusion; assumed ok after two non-objections, REVERSIBLE,
   flag to reopen)
7. Unit tests are agent-private scaffolding for the builder; E2E proofs are
   the public trust layer, the only tests a human ever sees. (Q3 synthesis)

## Approaches Considered

### Approach A: Panel slice + scripted loop (minimal viable)
One new human-panel view on the existing renderer, minimal agent-skills files,
facturas flow with airlock, static nutrition card, all built in parallel.
Ruled out: ships fastest if ARCA cooperates, but the ARCA unknown sits on the
critical path with no protection.

### Approach B: Two projections, one model (ideal architecture)
Formal behavior-graph model with agent and human projections, skills writing
through an event log, proofs and airlock first-class. Ruled out: best
long-term trajectory and the platform the 10x needs, but an architecture
project inside a 10-day film shoot.

## Recommended Approach

Approach C: proof core first, panel flexes (approved by D4=C). Days 1-2 crack
homologacion plus the E2E proof core headless behind a kill gate: pass means
full speed on panel plus label plus film, fail means pivot to compress with
eight days left. Panel and label flex to remaining time; agents build the panel
in parallel once the gate passes. Rationale: answers the biggest risk with a
decision date instead of hope; converges to the minimal viable on gate pass.

Kill gate (pinned): PASS means a headless test CAE returned through the proof
core within 48h of the day-1 access attempt, judged by Dino. Anything less
(certs alone, token alone, no response) means pivot. The pivot is one-way once
taken: compress owns the remaining schedule, late-arriving certs do not
reverse it.

Foundation (pinned): no ship required for the hackathon. Approach C builds on
the working tree as-is; the feat/typed-belts ship decision stays open until
after the video. The human panel rests on the existing floor-ui renderer, which
already provides generic machines, belts, cites, and edge cards (proven when
the frontend slice needed no client changes). Fallback if the tree breaks: the
current floor-ui as-is, panel as behavior cards only.

Minimal v1 floor: during the live build the viewer sees one machine card rise
per flow stage (ask, build, file, prove); during the run the invoice packet
flows visibly along belts (data in, CAE out); own input enters via the ask box
plus file drop; every machine carries a proof light (green/red from its latest
E2E) with click-through to the proving input and output. Flexes if time runs
short: ticker richness, label depth, film polish, multi-machine layout. Cut ladder (D13, ordered): ticker richness, label
depth (static card stays), extra film polish, multi-machine flourishes.
Never cut: proof core, airlock, error states, replay chrome, layout. Cannot
flex without violating P3: cards rising during the build plus visible
flow-through of the viewer's own input. Error states (R6): unreachable,
bad cert, rejected invoice, timeout, each with plain-words copy and a next
step; pre-proof light is off or amber trying, never red. Pre-live states
(D5): the empty bay shows invitation copy plus the ask affordance (this is
the demo's first frame); stage machines rise via ghost-to-solid as the
authored beat; stale ticker entries are kept and marked STALE, never
silently dropped. Run states (D6): partial proof shows the aggregate plus
per-stage lights; errors persist with copy and next step until dismissed or
superseded; CAE arrival flips the gate lamp with its readout; replay wears
persistent RECORDED PROOF chrome, never passed as live. Fixed layout (D3):
floor owns the pixels with one machine rising per stage; ticker is an
append-only readout in the 56px top strip next to a proof N-of-M aggregate;
ask plus file drop live in the 72px dispatch console; the airlock is a gate
at the floor edge; the label opens in the drawer.
```
+--------------------------------------------------------------+
| TOP STRIP: worker | proof N-of-M | ticker readout | last-chg |
+--------------------------------------------------------------+
| FLOOR: ASK -> BUILD -> FILE -> PROVE (machines rise)         |
|   packet flows on belts --> [CAE gate]  [AIRLOCK GATE edge]  |
|                                              +-------------+ |
|                                              | DRAWER:     | |
|                                              | label/inspect| |
|                                              +-------------+ |
+--------------------------------------------------------------+
| DISPATCH: ask input + file drop + SEND                       |
+--------------------------------------------------------------+
```
Machine ontology (D4): the toaster view shows stage machines
(ASK/BUILD/FILE/PROVE) with Saira nameplates, distinct from the code floor's
file-machines; one legend entry tells them apart. Cites are per-edge evidence
references shown in the drawer. Journey storyboard (D7): curiosity at the
empty bay, rising tension as stages prove one by one, CAE arrival as the
climax, label as the take-home; failures play as scenes with copy plus next
step (R6 states); replay is framed as replay (R8 chrome); the label carries
the retell so a viewer can explain the system afterward. Naming (D12): the first frame carries the
Artifex wordmark; the panel earns "the toaster" when the first machine
rises. Visual package
(D8): vocabulary is machines and plates, never cards: stage machines with
roofs, lamps, and glyphs; belts are the layout; the nutrition label is the
single deliberate plate. Airlock: bay-door gate at the floor edge with
hazard-striped border; one plain Instrument Sans sentence
(Sending/To/Nothing else); secrets as solid mask blocks with MASKED label;
items-crossed counter, 0 for compress. Label: one plate, four bands
IN/OUT/PROVED/CHANGED, mono tnum values, masked fields, timestamp. Ticker:
append-only strip readout, no marquee, entries marked trying/proven. Lamps:
proven is a filled square-plate lamp with check glyph plus PROVEN label;
trying is hollow dashed muted plus TRYING; failed is red with X plus
FAILED; amber reserved for inferred-only claims. One-job rule: lights say
proven, machines say what exists, ticker says what is happening now; packet
is a belt dash; ghost-to-solid is the one authored beat. Film-readiness
(D9): film scale bumps minimum label size and stroke widths ~1.25x over
compact-operate, verified on an exported frame; the label exports as a
legible standalone image; UI language picked with one plain-words gloss per
jargon term (CAE, monotributo, homologacion). DESIGN.md amendments (D10,
flagged for build): Decisions Log entry for the audience pivot (solo
developers to code-indifferent humans plus a filmed artifact) confirming
amber stays inferred-only and trying renders hollow-muted; mode-per-surface
update (toaster panel is Persuade/Experience, code floor and rest stay
Operate); plain-words register (Instrument Sans sentences, mono only for the
viewer's own inputs and outputs, Anton bays, Saira nameplates). Motion scope (D11): film-only fixed frame; responsive
viewports deferred past the video; reduced motion renders the beat as an
instant state change with static dashes while the ticker still appends.

Narration rule (v1, satisfies P2): ticker and cards mark every unproven item
as trying (in-progress style, never stated as fact); factual claims render
only with their linked E2E proof id; each proof click-through shows the exact
proving input and output.

Fallback: compress loop (warm). Ask: "shrink my PDFs." Poke: drop your own
PDF. Proof: E2E run asserting a smaller valid PDF out. Airlock beat: the
boundary display shows zero egress (fully local transform, "nothing leaves
the machine"). Label: standard in/out/proof/changes card. Stays warm during
days 1-2: PDF tooling picked, one fixture PDF ready, proof sketch written.

## Success Criteria

- The video shows the full loop: ask, built live, poked with own input, real
  test CAE through the airlock, nutrition card shared. Done means a
  non-programmer can retell what the system does and why it is trusted without
  hearing code words.
- Kill gate resolved by day 2: ARCA path proven or compress pivot taken.
- No secret and no production touch in repo, panel, logs, or video frames
  (reconciled clean surfaces; pre-publish check green).

## Distribution Plan

Repo plus recorded video for the hackathon. Local-first run stays (bun server
on localhost; floor.sh loop for lifecycle). Share-a-poke links and one-click
packaging deferred post-hackathon. Existing repo CI covers gates; no new
pipeline for v1.

## Next Steps

2. Days 1-2: E2E proof core headless for the facturas flow. Gate review at 48h.
   Spike first (R3): import arcasdk under bun and reach the homo WSDL; pass

3. Panel slice: human behavior-cards view on the existing renderer, narration
   ticker, proof lights. Transport (R5): build events, proof records, and
   ticker entries ride the existing snapshot/patch channel; the panel
   subscribes like the runs feed.
4. Agent skills v1: narrate intent, attach proofs, update the panel model.
5. Airlock beat plus nutrition label. Record the loop and the stunt. Edit.
   Film backup (R8): gate run archives its proof; film-day fallback replays
   it with an on-screen recorded-proof label, never passed as live.
6. Ongoing gate rule (R2): register every new file in the typecheck list and
   keep coverage breadth per change; never batch gate plumbing to the end.
