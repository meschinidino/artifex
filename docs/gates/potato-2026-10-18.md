# Potato gate (design T8, D3/D15) — run 2026-10-18

Verdict: **PASS** on both budgets, on the named weak machine.
This is one half of the T8 gate; the comprehension half is recorded in
[comprehension-protocol.md](comprehension-protocol.md) and has **not** run yet.

## Criteria (from the design ledger)

- D3: Artifex-owned processes total **≤ 150 MiB** on a ~1,000-file
  repo (single Bun server process since the D14 fold; parser
  batches are short-lived subprocesses of it).
- D15: browser tab measured separately, **fail threshold 500 MB**;
  weak machine named before measuring: this dev Mac (Apple M4 Pro,
  24 GB, macOS 27.0.1 arm64; recorded at spike end).
- Interaction budget (`specs/tech_stack.md`): 60 fps floor
  interaction.

## Method

Real server (`bun run server/index.ts --agent none`) over
generated fixtures (`spike/rss/gen-corpus.ts`, 10 folders), one
boot per size. RSS = server process + live children via `ps`,
median of 3 samples after HTTP 200 plus a 2 s settle. Tab and
frames measured through the same headless-Chromium driver the
E2E suite uses, on the 1,000-file fixture: tab = the dedicated
renderer process RSS; frames = `requestAnimationFrame` deltas
over 3 s while synthetic wheel events pan/zoom the canvas.

## Results

| Files | Boot to HTTP 200 | Server RSS (median) |
|---|---|---|
| 500 | 1 s | 75 MiB |
| 1,000 | 1 s | **92 MiB** |
| 2,500 | 3 s | 135 MiB |
| 3,000 | 3 s | 153 MiB |
| 3,500 | 4 s | 163 MiB |
| 5,000 | 5 s | 203 MiB |

- **D3 at the gate size (1,000 files): 92 MiB ≤ 150 MiB — PASS.**
- The 150 MiB crossing sits between 2,500 and 3,000 files; that
  measurement set the boot ceiling `MAX_FLOOR_FILES = 2_500`
  (~10% headroom), shipped the same day.
- **Tab (1,000 files): renderer process 139 MiB; the whole
  dedicated headless instance (browser + GPU + utility +
  renderer) ≈ 355 MiB — both under the 500 MB fail threshold.**
  Page JS heap was 9.5 MB of that. Earlier work had only the
  JS-attributed number (`measureUserAgentSpecificMemory`); this
  run replaces it with whole-process RSS.
- **Frames (1,000 files, wheel pan/zoom): 364 frames, p50 8.3 ms,
  p95 9.1 ms, max 16.9 ms, 0 frames over 25 ms.** The display
  runs at 120 Hz, so p50 reflects the refresh interval; no frame
  missed even a 60 fps budget by more than 0.2 ms.

## Caveats (recorded, not rounded away)

- Synthetic fixture files are small and uniform; real repos keep
  more per file (parse results, connections). The ceiling's 10%
  headroom is the recorded compensation, not a proof for every
  repo shape.
- One boot per size (RSS samples within a boot were identical to
  the MiB). Tab and frames are single samples on a headless
  shell, not a human-driven browser session.
- Agent dispatch was off (`--agent none`); a live `muse` worker
  is the agent's own process, outside the Artifex-owned budget
  per D3's wording.

## Gate decision (D21)

Potato: **PASS**. Comprehension: **NOT RUN** — it needs a non-technical
viewer and a repo named by the builder; no agent can score it.
Per D21 the T8 gate as a whole is therefore **not passed**, and
the remaining gated scope (T6 ask-why polish, T7 DB zone) stays
gated until the comprehension session is scored with
[comprehension-protocol.md](comprehension-protocol.md). Recorded deviation:
the dispatch half of T6 already shipped with the ghost layer
(PR #11) before this gate was scored; the gate now applies to
what remains.
